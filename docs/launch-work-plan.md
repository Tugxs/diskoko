# خطة تجهيز الإطلاق

مرجع الخطة: مراجعة جاهزية الموقع بتاريخ 20 أكتوبر 2026. الأسماء التالية تجمع تفاصيل التقرير ولا تختزل معايير قبولها. تقفل كل خطوة بدليل الاختبار والنشر المناسبين لها؛ المراجعة لا تصبح شهادة عدم قابلية للاختراق.

| الخطوة | نطاقها ومعيار الإغلاق |
|---|---|
| 1 الدخول وإدارة الموقع | هوية موثقة، تدوير جلسات، OAuth مقيد وغير قابل لإعادة الاستهلاك، وصول الإدارة وإعادة تحقق حديثة، logout/CSRF/cache؛ تفاصيل التنفيذ في launch-step-1-authentication.md |
| 2 حماية الموارد | حدود مبكرة قبل التحليل، حد عام وحساب وأداة، مفاتيح محدودة/TTL، ضغط ورفع متزامن، وقياسات عدم نمو الذاكرة |
| 3 قاعدة البيانات | اعتماديات الاتصال الداخلي/الخارجي، allowlist، TLS متحقق، ميزانيات الاتصال وأدوار DB واختبار استمرار كل الخدمات |
| 4 التعافي | نسخة واسترجاع في قاعدة مستقلة، مفاتيح محفوظة، RPO/RTO، تراجع متوافق؛ لا إسقاط بيانات الإنتاج |
| 5 الرصد والنشر | نبض الخدمات وأعمار الطوابير، تنبيه مجرّب، graceful shutdown، CI gate وnpm ci وبيئة تحقق |
| 6 العزل وعدم التكرار | حسابان/سيرفران/بوتان ومشرف محدود، CRUD/ملفات/تصدير/جدولة، تسابق وإعادة محاولة وأعطال، مراجعة جداول مشتركة وسياسة RLS |
| 7 الخدمات والتجارة | تنسيق توفر AI مع مشروعه المستقل، دفع يدوي واضح أو دفع/استرداد مثبت، دعم وحذف بيانات واحتفاظ وإلغاء تكاملات |
| 8 تجربة العميل | بدء جديد، حالات الاتصال، تعريب الحالات والتوقيت، تقليل قوائم النظرة والسجل والأدوات المتقدمة والخيارات المعلقة، محررات الجوال |
| 9 السعة والتوسع | حمل staging بمستخدمين مسجلين وبوتات وموسيقى وأكواد، قياسات CPU/RAM/DB/p95/errors، توزيع ملكية العامل وLISTEN والأقفال قبل التوسع الأفقي |
| 10 قبول الإطلاق | رحلة جديدة على البوت العام والخاص، تحقق بوابات الخطوات السابقة، دفعة أولى محدودة ومراقبة ثم قرار توسع بالأرقام |

التكلفة الإضافية، أو موافقة OAuth التي تتطلب تدخل صاحب الحساب، أو تجربة استرجاع/حمل لم تُنفذ: تسجل صراحة ولا توصف بأنها مكتملة. لا تتغير إعدادات مشروع AI في محادثة أخرى ضمن خطوات الموقع دون تنسيق مصرح به.
