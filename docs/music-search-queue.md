# Music search, queue entry and voice failure status

The existing slash option `رابط` accepts a supported YouTube URL, approved direct audio URL, or a bounded plain song/artist name. Plain names become `ytsearch:` queries to the configured Lavalink node; the first returned track is selected. There is no arbitrary source-prefix or URL-to-search fallback. Search availability depends on the node's YouTube search support. Existing slash names remain compatible.

The active panel has a separate Add next song button. Its modal takes the same input, appends at the end of the upcoming queue without replacing the current track, and reports the upcoming position. Guild/bot/command scope, current voice room, administrator override, configured DJ role, bounded resolution and 25-track queue remain enforced. A session that ended during lookup cannot be revived by the modal.

The 2 November 2026 production joins at 17:00:57, 17:01:35 and 17:03:24 UTC failed with `error: undefined`. This does not establish a permissions issue or repeat of earlier 429s. Shoukaku's REST error constructor overwrites message/status with fields from a provider JSON body; a nonstandard body loses HTTP status. A custom REST implementation preserves response HTTP status independently, discards unsuccessful bodies and does not log credentials, voice data or session paths. Join errors now expose a safe classification. A confirmed 404 retires an idle manager so the next user attempt establishes a new node session; an active manager serving other guilds is not stopped. There is no automatic replay of voice joins.

No live destructive actions, provider credentials, paid infrastructure changes, or verified audio acceptance were performed by these tests. A fresh live attempt is required to identify the previously discarded upstream status and establish playback success. Instrumentation and search support must not be described as proof that an unknown provider failure is resolved.
